# 前端项目启动说明

## 一、开始之前：把环境准备好

本指南写给刚拉取本项目代码、想把服务跑起来的你。整个启动过程共四步：安装常规依赖、恢复离线依赖包、确认后端服务、启动验证，顺利情况下 20 到 40 分钟可以完成（主要耗时在依赖下载）。先检查本机环境是否满足要求。打开命令行，依次执行以下两条命令，核对输出是否与要求一致：

```bash
node -v    # 应输出 v16.20.2
npm -v     # 应输出 9.x
```

**表 1-1 环境要求与自检命令**

| 组件 | 要求 | 自检命令 | 不符合时 |
|---|---|---|---|
| Node.js | 16.20.2（必须）<br>14.21.3（可选） | `node -v` | 用 nvm / volta 切换版本 |
| npm | 9.8.x | `npm -v` | Node 自带，随 Node 一起处理 |
| 可用内存 | 不低于 16GB | 任务管理器查看 | 启动脚本已内置 16GB 上限参数 |
| 操作系统 | Windows / Linux 均可 | — | Windows 建议安装 Git Bash |

另外确认你手里的材料完整：源代码目录 hby-admin，以及与它同级的 resources 文件夹（离线依赖包）。两者必须在一起，第三步会用到 resources；如果你只拉到了源码没有 resources，请先向代码提供方索取。

## 二、第一步：安装常规依赖

进入源码目录，把 npm 源切换到国内镜像（npm 官方源在部分网络环境无法访问，切换后可避免安装卡住），然后执行安装：

```bash
cd hby-admin
npm config set registry https://registry.npmmirror.com
npm install --legacy-peer-deps
```

**预期结果：**命令执行完毕且无致命报错，生成的 node_modules 目录约 1.5GB。安装日志里出现 vab-icons、vab-quill 等包的 404 或 451 报错属正常现象——这些包已从 npm 仓库下架，任何网络都装不上，下一步用离线包解决；如果是其他包报 404，先执行 `npm config get registry` 确认镜像源已切换。

## 三、第二步：恢复离线依赖包（必做）

有 12 个依赖包已从 npm 仓库下架（请求返回 HTTP 451），无法通过 npm install 获得，缺失它们项目无法启动。随代码附带的 resources/node_modules 文件夹里是这 12 个包的完整离线副本（解包目录形态，含各自的嵌套依赖），把它们整体复制进项目的 node_modules 即可：

```bash
cp -r ../resources/node_modules/* node_modules/
```

> 以上命令假设 resources 与 hby-admin 在同一父目录下；如果你的目录层级不同，请把路径替换为 resources/node_modules 的实际位置。

| 包名 | 版本 | 用途 |
|---|---|---|
| vab-icons | 0.0.20 | 模板图标组件（依赖 vue-plugin-rely） |
| vab-quill | 0.0.4 | 富文本编辑器组件 |
| vab-player | 0.0.5 | 视频播放组件 |
| vab-count | 0.0.1 | 数字滚动组件 |
| vab-cropper | 0.0.3 | 图片裁剪组件 |
| vab-magnifier | 0.0.1 | 放大镜组件 |
| vab-contextmenu | 0.0.1 | 右键菜单组件 |
| vab-templates | 0.0.5 | 代码生成模板（仅开发期使用） |
| vue-plugin-rely | 2.6.14 | vab-icons 的运行时依赖 |
| zx-markdown-editor | 0.0.2 | Markdown 编辑器 |
| chalk-next | 5.1.2 | 控制台着色（chalk 的独立分叉） |
| chokidar-next | 4.0.14 | 文件监听（chokidar 的独立分叉） |

**预期结果：**node_modules 下能找到这 12 个目录。执行下面的校验命令，三条都不报错即表示依赖就绪：

```bash
ls node_modules/vab-icons/package.json
ls node_modules/vue-plugin-rely/package.json
node -e "require('./node_modules/element-ui/package.json')"
```

## 四、第三步：确认后端服务可达

前端页面的数据全部来自后端接口。开发模式下，前端把 /api 开头的请求代理到后端网关，默认网关地址是 http://127.0.0.1:9000（本机 9000 端口）。启动前端前，先按你的实际情况确认网关可达：

**情况 A：后端网关就在你本机。**先把后端服务跑起来（后端项目不在本前端仓库内），再继续下一步。

**情况 B：网关部署在内网其他主机。**打开 vue.config.js，把 devServer.proxy 中 target 的 http://127.0.0.1:9000 改为实际内网地址。文件里大量注释掉的候选地址都是历史环境的脱敏占位，直接忽略。

改完后可以快速自检一下：在命令行访问网关地址，只要有任何 HTTP 响应（哪怕是报错页）都说明网络通了：

```bash
curl -I http://127.0.0.1:9000    # 有响应即可，不要求 200
```

**预期结果：**网关地址可访问。关于接口地址还有两处配置需要知道：开发环境的接口前缀 /api 在 src/config/net.config.js 的 baseURL；生产环境的完整接口地址在同一文件的 getUrl 函数中按环境编号配置，当前全部是脱敏占位值（例如 http://www.example.com/api），部署生产包时替换为实际地址即可。

## 五、第四步：启动并验证

一切就绪，启动开发服务器：

```bash
npm run serve
```

首次编译需要等待一段时间。当控制台出现类似 `App running at - Local: http://localhost:10000/` 的输出时，前端就已经启动成功了。用浏览器打开 http://localhost:10000，能看到系统登录页面，说明本指南的目标已达成。

**预期结果：**控制台输出 Local: http://localhost:10000，浏览器可以打开登录页。

后续要构建生产包时执行 `npm run build`，产物在 dist 目录；部署前记得把 net.config.js 中的生产接口地址从占位值改为实际地址。

## 六、启动成功之后：几条重要提醒

1. 日常开发请始终用 `npm run serve` 启动。vab-icons 所依赖的 vue-plugin-rely 包含校验逻辑，在非 development 模式下若校验不通过会执行破坏性的目录清理操作。项目 .env 中已配置模板预览授权密钥（VUE_APP_SECRET_KEY=preview），development 模式下正常运行，请不要改动它。

2. 不要执行 `npm run update`：它引用的 registry.npm.taobao.org 域名早已停用，跑了必然失败。`npm run clear` 依赖 cnpm，未安装 cnpm 时同样不可用。

3. 需要调整接口地址时只动两处：开发代理 target（vue.config.js）和生产地址（src/config/net.config.js）。项目里同时存在 package-full.json、package-minimal.json 等多份清单和三份 vue 配置，均为模板裁剪的中间产物，一切以 package.json 和 vue.config.js 为准。

## 七、启动失败？对照这张表排查

**表 7-1 常见报错与处理**

| 症状 | 原因与处理 |
|---|---|
| npm install 报 vab-* 相关 404 / 451 | 包已下架，属正常现象。按第二步用 resources 离线包恢复即可 |
| npm install 长时间无响应 | 镜像源未生效：`npm config get registry` 检查，确认是 registry.npmmirror.com |
| 启动报 digital envelope / OpenSSL 错误 | Node 版本高于 16。nvm use 切回 16.20.2 后重新 npm run serve |
| 页面打得开但空白、接口全部报错 | 后端网关没跑或代理目标不对。按第三步确认 127.0.0.1:9000（或你的 target）可达 |
| 提示端口 10000 被占用 | 改 src/config/cli.config.js 的 devPort 为其他端口，重新启动 |
| 构建报 heap out of memory | 内存不足。关闭其他大型程序重试；仍溢出时调大脚本中的 --max-old-space-size |
| 登录时报加密异常 | 后端公钥接口未正常返回，找后端确认。前端内置 RSA 私钥已脱敏置空，依赖本地解密的功能不可用 |
| node --check 报 import 语法错误 | 源码是 ES Module 写法，该检查方式不适用，不影响 webpack 构建和运行，忽略即可 |

## 八、附录：关于代码脱敏

你拿到的代码已经过整体脱敏：公司、客户相关的真实地址全部替换为 example 系域名和 192.0.2.x 占位网段（共 476 个文件、约 1050 处）。这就是为什么本指南让你在第三步自行填写网关地址——占位值不代表任何真实环境。

模板下载 404、业务文档页 404、图片直传 OSS 不可用，均属脱敏的预期结果，不影响开发服务器启动。
